From PID Control to Reinforcement Learning

How tuning a line-following robot gave me an intuition for reward signals, policy gradients and the explore–exploit tradeoff.

When I was building the autonomous line-following robot that won Robofest Ghana 2025, I didn’t know I was learning reinforcement learning. I thought I was just tuning three numbers.

The robot had a single job: follow a black line on a white surface. An infrared sensor read the line position, and a motor controller adjusted the wheels. The bridge between sensor and motor was a PID controller: three coefficients that determined how the robot reacted to error.

The three numbers that control everything

Kp (proportional) says: the further you are from the line, the harder you should steer. Set it too low and the robot drifts lazily off the track. Set it too high and it oscillates wildly, overcorrecting left–right–left until it spins off the course entirely.

Ki (integral) says: if you’ve been slightly off for a while, accumulate that error and push harder. This fixes the subtle drift that Kp alone can’t catch: the robot that’s always 2 mm to the left, never quite centering. But too much Ki and the system winds up, building momentum that causes massive overshoot.

Kd (derivative) says: if you’re approaching the line quickly, ease off. It’s the damper, the brake, the thing that prevents Kp’s corrections from becoming oscillations. Too much Kd and the robot becomes sluggish, afraid to move.

# The core PID loop I ran on competition day
error      = sensor_position - target_center
integral  += error
derivative = error - previous_error

correction = (Kp * error) + (Ki * integral) + (Kd * derivative)

left_motor  = base_speed + correction
right_motor = base_speed - correction

previous_error = error

Those six lines of code won a national championship. But I spent weeks tuning them, running the robot, watching it fail, adjusting one coefficient, running it again. Dozens of iterations. Some runs the robot was too cautious, some too aggressive, and occasionally it nailed the line perfectly.

Then I opened an RL textbook

Months later, studying reinforcement learning for the first time, I kept having déjà vu. The vocabulary was different but the problems were identical.

PID tuning is manual policy optimisation. The policy is the PID equation. The parameters are Kp, Ki, Kd. The reward is “robot stays on line”. I was the optimisation algorithm, watching, adjusting, repeating. RL just automates me out of the loop.

The explore–exploit tradeoff was something I felt physically. Early in tuning, I tried wild Kp values (0.1, 5.0, 15.0) to understand the parameter space. Later, I made tiny adjustments around the best values I’d found. That’s exactly what epsilon-greedy and UCB formalise.

Reward shaping was intuitive too. At first my reward was binary: did the robot finish the course? That signal was too sparse. So I started watching intermediate behaviour: how smooth were the turns, how fast through the straight sections. I was decomposing a sparse reward into a denser signal, the same challenge every RL practitioner faces.

Even overfitting showed up. I tuned my PID specifically for the practice track in our lab. First competition run on a different track with tighter curves. The robot struggled. I’d overfit to my training environment. The fix was testing on multiple track layouts, which is domain randomisation by another name.

What this taught me about learning AI

The best way to understand an abstraction is to first do the concrete thing it abstracts. I didn’t learn PID from a textbook. I learned it from a robot that kept falling off a table. Because of that, policy gradients, reward functions and hyperparameter search don’t feel abstract to me. They feel like the robot.

If you’re starting out in ML and the maths feels disconnected: build something physical first. A robot, a sensor system, a control loop. The intuitions you develop from watching hardware fail in real time transfer directly to understanding why a network fails in a notebook.

The PID controller is a hundred years old. Reinforcement learning is the same idea with a bigger budget and more parameters. Understanding one deeply makes the other inevitable.
